# LAB 教学生成规范 V1.0

> 文档性质：音乐风格 / 歌曲分析到 LAB 课程生成的产品与内容规范  
> 适用对象：备课后台、AI 教学方案生成、LAB 前端、内容审核  
> 当前基准案例：PHONK LAB  
> 版本目标：先保证课程结构稳定、可审核、可复用，再制作自动生成 Skill

---

## 1. 规范目标

将一种音乐风格或一首具体歌曲，转化为一套适合小学 5–6 年级、可在普通教室完成的音乐 LAB。

每套 LAB 都应让孩子经历以下过程：

```text
先听见风格
→ 拆开学习节奏与特色声音
→ 用身体或身边物品练习
→ 分组合作
→ 录制自己的声音
→ 编排成 30–60 秒作品
→ 全班演出
```

最终生成结果不是一篇教案，而是一份可以直接驱动 LAB 页面和声音播放的结构化课程数据。

---

## 2. 产品原则

### 2.1 屏幕是引导出口，不是孩子的主要输入入口

- 屏幕负责播放、解释、倒计时、当前拍点提示和作品编排。
- 孩子的主要活动发生在教室中：听、说、拍、敲、摇、录制和集体演奏。
- 不要求每个孩子持有设备，不把连续点击屏幕设计成主要学习行为。
- 编排和播放控制可以由老师在屏幕上完成。

### 2.2 先学习声音，再使用声音

课程必须先让孩子听辨并练习核心元素，再进入录制和编排。不能一开始就展示复杂音轨编辑器。

### 2.3 每页只承担一个明确任务

- 删除流程说明、角色职责等后台信息。
- 不重复出现相同功能。
- 页面文字只保留完成当前任务所需的内容。
- 操作按钮原则上不超过 3 个：返回、播放 / 暂停、继续。

### 2.4 内容必须属于当前音乐

每个教学元素都必须能解释它为什么属于当前风格或歌曲。不得为了凑满页面而加入无关乐器、环境音或动作。

### 2.5 使用“功能类比”，不宣称生活声音等于专业乐器

标准表达：

> 拍腿声音较低、起音清楚，可以承担类似 Kick 的稳定脉冲功能。

避免表达：

> 拍腿就是 Kick。

### 2.6 体验优先于术语记忆

专业名词可以出现，但必须同时提供 10 岁孩子能理解的一句话解释和一次可听见的示范。

### 2.7 页面语气跟随音乐气质

标题、提示词和段落名称应反映当前音乐的力度与气质。例如 PHONK 可以使用“进入、爆发”，Bossa Nova 更适合“加入、轻轻留白、全体回来”。不得只替换乐器名称而保留同一套语言。

## 3. 备课后台输入规范

### 3.1 必填输入

| 字段 | 说明 | 示例 |
|---|---|---|
| 分析对象 | `style` 音乐风格或 `track` 具体歌曲 | `style` |
| 名称 | 风格名或歌曲名 | PHONK |
| 年级 | 默认小学 5–6 年级 | 五年级 |
| 课程时长 | 建议 35–45 分钟 | 40 分钟 |
| 班级人数 | 用于分组建议 | 36 人 |

### 3.2 可选输入

| 字段 | 作用 |
|---|---|
| 艺术家 / 版本 | 避免同名歌曲分析错误 |
| 音频文件 | 获取实际 BPM、段落和音色；具体歌曲精确分析时建议提供 |
| 参考链接 | 只作为来源定位，不默认获得音频使用权 |
| 教室物品 | 限制可推荐的生活声音来源 |
| 可分组数量 | 默认 3 组，建议 2–4 组 |
| 是否允许录音 | 决定第 5 页使用真实录音还是预置示范声 |
| 可用设备 | 电脑扬声器、投影、麦克风等 |
| 作品目标时长 | 默认 45 秒，允许 30–60 秒 |
| 老师补充目标 | 例如“重点学习切分节奏” |

### 3.3 输入可信度

- 只输入风格名：生成“典型风格 LAB”。
- 只输入歌曲名：必须标记为“知识推断”，不能假装完成了音频分析。
- 输入歌曲名与音频：可以生成“具体歌曲 LAB”。
- 歌曲身份不明确时，必须要求补充艺术家、版本或音频，不得猜测。

## 4. 音乐分析规范

AI 必须先生成分析卡，再生成 7 页课程。

### 4.1 分析维度

| 维度 | 必须回答的问题 |
|---|---|
| 一句话识别 | 孩子最容易听懂的风格特点是什么？ |
| 速度与拍号 | BPM、拍号、整体速度感是什么？ |
| Groove | 音乐如何向前运动？稳定、摇摆、弹跳、切分还是其他？ |
| 核心节奏 | 哪 2–4 个节奏层最值得孩子练习？ |
| 核心乐器 | 哪些乐器承担脉冲、重音、细分、低音或旋律？ |
| 特色音色 | 哪 1–3 个声音让人容易认出这种风格？ |
| 组织结构 | 常见的进入、堆叠、留白、高潮方式是什么？ |
| 动态变化 | 音乐如何从少到多、从轻到重？ |
| 可表演映射 | 哪些可用身体或安全物品完成？ |
| 数字声音边界 | 哪些必须由浏览器、采样器或合成器完成？ |

### 4.2 事实与教学选择分离

分析数据分为两层：

1. `musicAnalysis`：对音乐本身的判断。
2. `teachingSelection`：从分析结果中选择适合本节课的内容。

不得因为某个元素容易教学，就错误地宣称它是该风格的核心特征。

### 4.3 核心元素筛选规则

进入课程的元素必须至少满足以下 3 项：

- 在该风格或歌曲中容易听见。
- 对理解音乐有明显作用。
- 10 岁孩子能在短时间理解。
- 可以被身体、物品、声音录制或浏览器声音表现。
- 可以在最终作品中成为独立音轨。

每套 LAB 建议选择：

- 2–4 个节奏元素；
- 1–3 个特色音色或旋律元素；
- 最终保留 3–5 条编排音轨。

## 5. 生活声音映射规范

所有映射统一采用以下链路：

```text
声音来源 Source
+
发声动作 Action
→ 声音属性 Sound Properties
→ 音乐功能 Musical Function
→ 数字音乐元素 Digital Mapping
```

### 5.1 必填声音属性

- 音高区域：`low / mid / high / pitched / unpitched`
- 起音：`soft / medium / hard`
- 时长：`short / medium / long / continuous`
- 明亮度：`dark / neutral / bright`
- 连续演奏能力：`low / medium / high`
- 音高稳定性：`stable_pitched / approximate_pitched / unpitched`

### 5.2 音乐功能

- `pulse`：稳定脉冲
- `accent`：重音
- `subdivision`：节拍细分
- `low_percussion`：低频打击层
- `high_percussion`：高频打击层
- `continuous_texture`：连续纹理
- `pitched_percussion`：有相对音高的打击声
- `sustained_sound`：持续音
- `fx`：效果音或拟音

### 5.3 映射置信度

- `A`：声音属性和音乐功能高度匹配。
- `B`：适合教学类比，但不是同一种音色。
- `C`：只适合探索比较，不作为固定替代。

例如：

| 教学声音 | 音乐功能 | 数字类比 | 置信度 |
|---|---|---|---|
| 拍手 | Accent | Clap-like | A |
| 拍腿 | Pulse / Low Percussion | Kick-like | B |
| 安全金属容器轻敲 | Pitched Percussion | Cowbell-like | C |
| 浏览器合成器 | Bass | 808 Bass | A |

808 Bass、稳定旋律等无法由普通物品准确完成的声音，应由浏览器或合成器提供，不得强行寻找生活物品替代。

## 6. 七页 LAB 页面规范

### 01 风格入口

**作用**：建立对音乐的整体印象。

必须包含：

- 风格或歌曲名称；
- 40–80 字儿童版介绍；
- 3 个最值得听辨的声音线索；
- 10–20 秒试听；
- 一个主按钮“开始学习”。

交互要求：孩子先完整听，不要求做动作；播放时可视觉提示当前出现的声音线索。

### 02 节奏拆解

**作用**：分组学习该音乐最重要的节奏层。

每个节奏元素必须包含：

- 专业名称与中文解释；
- 声音拟声词；
- 在音乐中的作用；
- 身体动作或安全物品；
- 1–2 小节简单练习节奏；
- 播放时当前音符高亮。

建议分为 2–4 组，每次只展示一组。不得加入与当前音乐无关的通用动作。

页面标题可以根据风格动态生成，不固定称为“身体里的鼓”。节奏来源可以是鼓、吉他、贝斯、打击乐或其他真正影响该音乐律动的元素。

### 03 节奏合奏

**作用**：让已学习的节奏层逐步叠加。

标准流程：

```text
4 拍倒计时
→ 第 1 组进入
→ 第 2 组加入
→ 第 3 组加入
→ 全体合奏
```

屏幕必须显示：

- 每组的节奏提示；
- `准备 / 现在进入 / 继续演奏 / 一起演奏` 状态；
- 当前拍点高亮；
- 开始 / 暂停和返回按钮。

### 04 特色声音

**作用**：认识决定该风格辨识度的音色、乐器、和声或旋律元素。

允许的特色元素类型：

- `instrument`：乐器；
- `timbre`：音色；
- `harmony`：和声或和弦色彩；
- `melodic_motif`：旋律动机。

每个元素必须包含：

- 对应乐器或设备图片；
- 专业名称；
- 儿童版音色说明；
- 独立播放按钮；
- 可用身体 / 物品体验，或明确标记“由浏览器播放”。

不重复使用无关角色图代替乐器图。

### 05 录音工坊

**作用**：把孩子制造的声音转化为作品素材。

默认录制第 02 页中的 2–3 个可表演节奏元素。每条录音建议 2 小节。

录音音轨与最终编排音轨不必完全相同。难以由身体或物品准确完成的吉他、低音、和声等，可以作为浏览器音轨直接进入第 06 页。

标准流程：

```text
选择音轨
→ 听示范
→ 4 拍倒计时
→ 录制 2 小节
→ 回放
→ 保留或重录
```

要求：

- 录音不是必选条件；没有权限或设备时提供示范声。
- 不进行儿童能力评分。
- 不要求填写姓名等个人信息。
- 清楚提示当前录制的是哪一种声音。

### 06 歌曲编排

**作用**：用已学习和录制的声音完成一首 30–60 秒作品。

编排采用“段落开关”，不让老师逐个编辑大量小节格子。

要求：

- 3–5 个段落；
- 3–5 条音轨；
- 每个段落可以开启或关闭音轨；
- 支持试听单个段落和完整作品；
- 孩子录制的节奏声与浏览器特色声音可以混合；
- 页面实时显示预计作品时长。

小节数按速度计算：

```text
建议小节数 = 目标秒数 × BPM ÷（60 × 每小节拍数）
```

将结果取最接近的 4 小节倍数，并确保最终时长为 30–60 秒。默认目标时长为 45 秒。

示例：PHONK 为 125 BPM、4/4 拍，24 小节约为 46 秒，因此当前 24 小节方案成立；其他速度不能直接照搬 24 小节。

### 07 全班演出

**作用**：把完成的编排变成全班分工演出。

必须包含：

- 各组当前负责的声音；
- 4 拍倒计时；
- 段落进度；
- 当前需要进入的组；
- 当前拍点或节奏提示；
- 排练单段与完整演出两种播放方式。

第 07 页就是最终演出，不再增加独立的第 08 页。

## 7. 页面间状态与导航

- 7 页都必须有“返回上一级”。
- 第 02 页返回时，优先返回上一个节奏小组；第一组再返回第 01 页。
- 返回不能删除已完成的录音和编排。
- 进入下一页前只检查必要条件，不设置分数门槛。
- 播放离开当前页时必须停止，避免声音叠加。
- 刷新页面后，已保存的草稿应尽可能恢复。

## 8. 儿童语言规范

### 8.1 专业词解释模板

```text
专业名称（简单中文）
它听起来……
它在音乐里负责……
```

示例：

> Hi-Hat（踩镲）：像“呲呲”的细碎声音，常常把大拍之间的小空格填满。

> 808（电子低音）：来自鼓机的低音鼓，拉长以后像贝斯一样很低、很重。

### 8.2 文案限制

- 一段说明建议不超过 80 字。
- 一句话尽量不超过 25 字。
- 先使用听觉感受，再解释专业作用。
- 不使用“频谱、包络、瞬态”等未解释术语。
- 不写“先听，不需要做动作”等过程介绍；通过按钮状态和页面交互表达。

## 9. 声音资源规范

### 9.1 声音来源优先级

1. 孩子或老师在课堂录制的声音；
2. 浏览器实时合成声音；
3. 已授权、可随产品分发的预置采样；
4. 具有明确授权范围的生成声音；
5. 具体歌曲的短试听仅在具备合法使用条件时提供。

### 9.2 浏览器声音最低要求

- 普通电脑和投影扬声器上能够听见。
- 不依赖超低频才能辨认。
- 第一次用户点击后再启动声音。
- 播放、暂停、重新开始状态明确。
- 同时播放的声音数量受控，避免失真。

### 9.3 具体歌曲边界

- 分析歌曲不等于获得歌曲传播权。
- 可以学习 BPM、节奏结构、乐器作用和编排方法。
- 不默认复制原曲音频、完整旋律或受保护采样。
- 对外发布前必须确认试听素材和采样的使用权。

## 11. 生成流程

```text
1. 接收备课输入
2. 判断是风格课程还是具体歌曲课程
3. 生成音乐分析卡
4. 选出适合教学的核心元素
5. 完成生活声音与数字声音映射
6. 生成 7 页课程草稿
7. 计算段落、小节数和作品时长
8. 检查专业名词、难度、安全和版权
9. 老师预览并修改
10. 发布为 LAB 课程数据
```

AI 生成后必须经过老师确认，不能自动直接发布到学生端。

## 12. 老师审核清单

### 音乐准确性

- [ ] 核心节奏确实属于该风格或歌曲。
- [ ] 特色声音具有辨识度，不是随意选择。
- [ ] BPM、拍号、段落信息有依据。
- [ ] 推断内容已清楚标记，没有伪装成音频分析结果。

### 教学可用性

- [ ] 7 页之间形成“听—学—合—录—编—演”的连续过程。
- [ ] 每页只有一个主要任务。
- [ ] 每个专业词都有儿童版解释和试听。
- [ ] 每个分组任务可以在短时间内完成。
- [ ] 最终演出能对应第 06 页的实际编排。

### 交互体验

- [ ] 每页都能返回上一级。
- [ ] 播放时有倒计时、当前拍点或段落提示。
- [ ] 页面切换后不会继续播放上一页声音。
- [ ] 作品编排不需要逐格编辑大量小节。
- [ ] 作品总时长为 30–60 秒。

### 安全与隐私

- [ ] 物品适合儿童使用且发声动作明确。
- [ ] 没有玻璃、锋利边缘、危险容器等材料。
- [ ] 小颗粒容器已经密封并要求老师检查。
- [ ] 不引导孩子用力拍击脆弱身体部位。
- [ ] 录音不要求姓名、学校等个人信息。

### 声音与版权

- [ ] 浏览器声音能在普通扬声器上听清。
- [ ] 所有内置声音都可合法随产品使用。
- [ ] 具体歌曲分析没有默认复制原曲或受保护采样。

只有所有必选项通过后，课程状态才能从 `draft` 改为 `published`。

## 13. PHONK 基准案例

PHONK LAB 当前可作为 V1.0 的验收样例：

| 分析部分 | 教学选择 |
|---|---|
| 稳定、有冲击力的鼓组 | Kick、Clap、Hi-Hat 分组练习 |
| 节奏层逐步叠加 | 第 03 页依次进入并全体合奏 |
| 明亮、重复的金属旋律 | Cowbell 独立听辨与安全物品比较 |
| 低沉、持续的电子低音 | 808 由浏览器播放，不强行用物品替代 |
| 从少到多、爆发、留白、再爆发 | 5 段、24 小节、约 46 秒编排 |
| 自制节奏素材 | 录制 Kick、Clap、Hi-Hat，再参与编排 |

新的音乐类型只有达到与本案例相同的完整度，才视为成功生成。

## 14. V1.0 范围与后续工作

### V1.0 包含

- 风格名或歌曲信息输入；
- 结构化音乐分析；
- 7 页课程生成；
- 身体 / 物品 / 浏览器声音映射；
- 30–60 秒作品编排；
- 老师审核后发布。

### V1.0 暂不包含

- 自动获取或下载商业歌曲；
- 自动解决歌曲版权授权；
- 对儿童演奏进行评分；
- 自动识别每位孩子；
- 多人同时使用个人设备操作；
- 完整专业数字音频工作站功能。

### 后续制作顺序

1. 依据本规范确定正式 JSON Schema。
2. 将 PHONK 课程改为读取 JSON，而不是写死在页面中。
3. 制作 `lab-lesson-generator` Skill。
4. 制作备课后台的“输入—生成—审核—发布”流程。
5. 用第二种音乐风格进行复用测试并修订规范。
